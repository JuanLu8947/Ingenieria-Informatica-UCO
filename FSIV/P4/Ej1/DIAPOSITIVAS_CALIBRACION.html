📷 Calibración de Cámara

Obtención de Parámetros Intrínsecos con OpenCV

FSIV - Práctica 4 - Ejercicio 1

🎯 Objetivos

Calibrar cámara, corregir distorsión, y almacenar parámetros

🎯 ¿Qué es la Calibración de Cámara?

Proceso de obtención de parámetros

La calibración nos permite obtener los parámetros intrínsecos de la cámara: matriz de cámara (fx, fy, cx, cy) y coeficientes de distorsión (k1, k2, k3, p1, p2).

💡 ¿Para qué sirve?

  • 🔧 Corregir la distorsión de la lente
  • 📐 Realizar medidas precisas en el mundo real
  • 🎮 Aplicaciones de realidad aumentada
  • 🤖 Visión por computador y robótica
Herramienta: Utilizaremos un tablero de ajedrez como patrón conocido 📋

📊 Parámetros Intrínsecos

Matriz de Cámara (K):

K = [fx 0 cx]
    [0 fy cy]
    [0 0 1 ]
Donde:
• fx, fy: Distancias focales en píxeles
• cx, cy: Coordenadas del punto principal
• k1, k2, k3: Coeficientes distorsión radial
• p1, p2: Coeficientes distorsión tangencial

🎯 Objetivo

Estos parámetros describen completamente cómo la cámara proyecta puntos 3D del mundo real a píxeles 2D en la imagen.

🔄 Proceso de Calibración

Pasos del algoritmo:

  1. 📷 Capturar múltiples vistas del tablero de ajedrez
  2. 🔍 Detectar esquinas con cv::findChessboardCorners
  3. ✨ Refinar posiciones con cv::cornerSubPix
  4. 📐 Generar puntos 3D del patrón conocido
  5. 🧮 Calibrar con cv::calibrateCamera
  6. 💾 Guardar parámetros en formato XML/YML
Requisito: Mínimo 9 vistas válidas para una buena calibración 📸

🎛️ Parámetros e Interfaz

📐 Parámetros del tablero

  • ROWS (04/20): ✅ Filas de esquinas internas - debe ser exacto (4 para logitech)
  • COLS (05/20): ✅ Columnas de esquinas internas - debe ser exacto (5 para logitech)
  • Board size: [5 x 4] - formato interno OpenCV (cols x rows)
  • Tamaño del cuadro: 3cm (--size=0.03) - escala real para medidas

🎯 Parámetros de refinamiento cornerSubPix

  • W_R (04/20): Radio de ventana - balance precisión vs robustez
  • ZZ_R (00/20): Radio zona cero - área excluida del cálculo
  • EPS (4/6): Criterio de convergencia - precisión mínima (0.001-1.0)
  • Max Iters (0100/1000): Máximo iteraciones - evita bucles infinitos

⌨️ Controles y efectos

  • ENTER: Capturar vista válida | SPACE: Saltar | ESC: Calibrar
  • ROWS/COLS incorrectos: Detección falla completamente
  • W_R bajo (3-5): Más preciso, sensible a ruido
  • W_R alto (10-15): Más robusto, puede desplazar esquinas
  • EPS alto: Para antes, menos refinamiento
  • Max Iters alto: Más iteraciones, mejor convergencia

⚡ Compilación y Ejecución

🔨 Compilar y testear el proyecto

mkdir build && cd build && cmake .. && make && ./test_common_code && cd ../..

🚀 Ejecutar calibración

# ✅ CONFIGURACIÓN CORRECTA para dataset logitech
../build-calibrate/calibrate --size=0.03 --rows=4 --cols=5 --verbose mi_calibracion.xml data/logitech_*.png

# ❌ Configuración anterior (NO funciona)
../build-calibrate/calibrate --size=0.03 --rows=6 --cols=9 --verbose mi_calibracion.xml data/logitech_*.png

# 📷 Desde cámara web (ajustar rows/cols según tu tablero)
../build-calibrate/calibrate --camera=0 --size=0.03 --rows=4 --cols=5 --verbose mi_calibracion.xml

# 🎯 Sin interfaz gráfica (para scripts)
../build-calibrate/calibrate --size=0.03 --rows=4 --cols=5 mi_calibracion.xml data/logitech_*.png
📋 Parámetros clave: Dataset logitech tiene tablero 6×5 cuadros = 5×4 esquinas internas → --rows=4 --cols=5

🔧 Corregir distorsión

# Imagen
../build-calibrate/undistort ./data/logitech.xml ./data/logitech_000_00*.png img_corregida.jpg

# Vídeo
../build-calibrate/undistort -v ./data/logitech.xml ./data/tablero_000_000.avi video_corregido.avi

⚠️ Webcam en WSL: Problemas y Soluciones

Punto de partida

Conectar una webcam en WSL es una tarea tediosa.
WSL no tiene acceso directo a dispositivos USB, por lo que las cámaras no aparecen automáticamente en /dev/video* como en Linux nativo.

Solución encontrada: usbipd + DroidCam

💻 usbipd (Windows)

Herramienta oficial para compartir USB con WSL

usbipd list
usbipd bind --busid X-X
usbipd attach --wsl --busid X-X

📱 DroidCam

Usar móvil Android como webcam

App móvil + Windows client
WiFi/USB connection
Aparece como cámara USB

🐛 Problemas reales encontrados

  • Sintaxis cambiada: usbipd wsl list ya no existe
  • "Device busy": Windows bloquea dispositivo si DroidCam está activo
  • Bind obligatorio: Error "Device is not shared" requiere bind previo
  • Conflictos de servicios: "Windows Camera Frame Server" no válido
  • Proceso inestable: Falla durante grabación de vídeo
  • Múltiples reintentos: Cerrar apps, bind, attach, repetir...

🎯 Lección aprendida

  • Para desarrollo: Dataset de imágenes es más confiable
  • Para demos: Evita configuraciones complejas en vivo
  • Para producción: Considera Linux nativo o Windows
  • Para educación: Enfócate en el algoritmo, no en la infraestructura
📊 Decisión final: Dataset logitech.zip - Mismo proceso educativo, cero problemas técnicos
