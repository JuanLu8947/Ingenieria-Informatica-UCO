🎨 ¿Qué es el Balance de Color?

Corrección del Balance de Blancos

Proceso automático para corregir las dominantes de color causadas por diferentes tipos de iluminación, restaurando los colores naturales de la escena.

Problema

Imágenes con dominante de color (azulada, amarillenta) debido a la temperatura de color de la luz

Solución

Algoritmos que identifican automáticamente la referencia blanca y ajustan todos los colores

Resultado

Imágenes con colores naturales y balance correcto entre canales RGB

Técnicas principales implementadas:

  • Gray World: Método estadístico global
  • White Patch: Método basado en píxeles más brillantes
  • White Patch con Percentil: Versión robusta contra outliers

🌍 Algoritmo Gray World

Principio Fundamental

Bajo iluminación neutra, la media de todos los píxeles de una imagen debe ser gris (aprox. 128,128,128 en RGB).

Implementación matemática:

1. color_promedio: m = mean(imagen_RGB)
2. factor de escala: α = (128/Rm, 128/Gm, 128/Bm)
3. imagen_corregida = imagen_original × factor_escala

Mi implementación en fsiv_gray_world_color_balance:

cv::Scalar mean_ = cv::mean(in);
out = fsiv_color_rescaling(in, mean_, cv::Scalar(128, 128, 128));

Ventajas:

  • Muy simple y rápido
  • Funciona bien en escenas con variedad de colores
  • Robusto para iluminación uniforme

Limitaciones:

  • Falla si la escena tiene dominante de color real
  • No funciona bien en escenas monocromáticas

⚪ Algoritmo White Patch

Principio Fundamental

Los píxeles más brillantes de la imagen corresponden a superficies blancas bajo la iluminación de la escena.

Dos versiones implementadas:

White Patch Clásico (p = 0.0):

1. luma = fsiv_convert_bgr_to_gray(imagen)
2. maxLoc = cv::minMaxLoc(luma) // posición del píxel más brillante
3. pixel_rgb = imagen.at<cv::Vec3b>(maxLoc)
4. max_rgb = cv::Scalar(pixel_rgb[0], pixel_rgb[1], pixel_rgb[2])
5. imagen_corregida = fsiv_color_rescaling(imagen, max_rgb, (255,255,255))

White Patch con Percentil (p > 0.0):

1. luma = fsiv_convert_bgr_to_gray(imagen)
2. hist = fsiv_compute_image_histogram(luma)
3. p_index = fsiv_compute_histogram_percentile(hist, 1.0-p)
4. mask = (luma >= p_index)
5. max_rgb = cv::mean(imagen, mask)
6. imagen_corregida = fsiv_color_rescaling(imagen, max_rgb, (255,255,255))

Parámetro p (Percentage):

  • p = 0.0: Usa solo el píxel más brillante (clásico)
  • p = 0.05: Usa el 5% de píxeles más brillantes (robusto)
  • p = 0.25: Usa el 25% de píxeles más brillantes (como ejemplo del enunciado)
  • p = 1.0: Equivale al método Gray World

⚖️ Función de Reescalado de Color

fsiv_color_rescaling - Función Base

Función fundamental que reescala los valores de una imagen para transformar un color objetivo de entrada en un color de salida deseado.

Implementación matemática:

cv::Scalar factor;
cv::divide(to, from, factor);
output = input.mul(factor);
Fórmula matemática:

factor = color_destino / color_origen
imagen_salida = imagen_entrada × factor

Para Gray World

from = media de la imagen
to = (128, 128, 128)

Para White Patch

from = píxeles más brillantes
to = (255, 255, 255)

Ventaja clave: Una sola función sirve para ambos métodos de balance

📊 Cálculo de Percentiles de Histograma

fsiv_compute_histogram_percentile

Encuentra el percentil especificado en un histograma, esencial para el White Patch robusto.

Mi algoritmo de acumulación:

double total_area = cv::sum(hist)[0];
float umbral = p_value * total_area;

float accumulated_sum = 0.0f;
for (int i = 0; i < hist.rows; i++) {
    accumulated_sum += hist.at<float>(i);
    if (accumulated_sum >= umbral) {
        return i;  // Percentil encontrado
    }
}
Objetivo: Encontrar el índice p tal que:
suma(h[0] + h[1] + ... + h[p]) ≥ p_value × área_total

Ejemplo práctico:

Para percentil 95% (p_value = 0.95) en imagen de 1000 píxeles:
• Umbral = 0.95 × 1000 = 950 píxeles
• El algoritmo acumula hasta alcanzar 950 píxeles
• Devuelve el índice donde esto ocurre

🔧 Funciones Auxiliares Implementadas

fsiv_convert_bgr_to_gray

Convierte imagen BGR a escala de grises usando cv::cvtColor con COLOR_BGR2GRAY

fsiv_compute_image_histogram

Calcula histograma de imagen en escala de grises con cv::calcHist (256 bins, rango [0,256))

Flujo de procesamiento para White Patch:

  1. Conversión: BGR → escala de grises (luminancia)
  2. Análisis: Histograma o búsqueda de máximo
  3. Selección: Píxeles más brillantes según parámetro p
  4. Cálculo: Valor de referencia blanca
  5. Aplicación: Reescalado de toda la imagen

Robustez del algoritmo:

La conversión a luminancia evita que dominantes de color afecten la selección de píxeles "blancos"

⚖️ Comparación de Métodos

Gray World (P=100)

  • Muy rápido
  • Funciona bien en escenas diversas
  • Puede fallar en escenas monocromáticas
  • Método estadístico global

White Patch Clásico (P=0)

  • Muy sensible a outliers
  • Funciona bien si hay blancos puros
  • Puede fallar con ruido o especularidades
  • Método basado en máximo local

White Patch Robusto (P=1-20)

  • Robusto contra outliers
  • Mejor en imágenes reales
  • Balance entre precisión y robustez
  • Método estadístico local

Recomendaciones de uso:

Imágenes de interiores con luz artificial:

White Patch con P=5-10% (robusto contra luces puntuales)

Paisajes y escenas naturales:

Gray World (P=100%) o White Patch con P=15-20%

Fotografías con objetos blancos claros:

White Patch clásico (P=0%) si no hay ruido
